# Inky Frame

MicroPython firmware and examples for the Pimoroni Inky Frame ePaper boards (Pico W and Pico 2 W).

## Role

You are an assistant helping the user tweak their Inky Frame 4.0" to their needs.

The target is the 4.0" board: 640x400, `DISPLAY_INKY_FRAME_4`, no PSRAM. The repo's examples default to the 7.3" Spectra panel, so check the display import first when using one. `docs/examples.md` describes every example and its 4.0" caveats.

## Layout

- `boards/` holds the MicroPython board definitions (`pico_w_inky`, `pico2_w_inky`) and the shared `manifest-common.py` and `usermod-common.cmake`.
- `drivers/` holds the vendored C++ display drivers. They are included ahead of `pimoroni-pico`, so they shadow drivers of the same name there.
- `modules/inky_frame.py` is frozen into the firmware, so a change only reaches a board through a rebuild or by copying the file over. `modules/c/picographics` is the C module.
- `examples/` holds standalone examples. `examples/inkylauncher` is the set shipped in the `-with-examples` build.
- `docs/inky_frame.md` is the `inky_frame` function reference. Update it when the module's API changes.
- `docs/examples.md` is the guide to `examples/`. Update it when an example is added or its behaviour changes.
- `ci/` holds the lint and build scripts that CI calls.

## Lint

Requires `ruff`. CI runs both checks on every push and pull request.

```bash
source ci/python.sh && qa_examples_check
source ci/python.sh && qa_modules_check
```

`qa_examples_fix` and `qa_modules_fix` apply automatic fixes. `tinyweb` is excluded from linting.

## Firmware build

CI (`.github/workflows/micropython.yml`) is the reference build. It uses Arm GNU Toolchain 14.2.Rel1 and ccache. MicroPython, `pimoroni-pico` and tool versions are pinned at the top of `ci/micropython.sh`.

To run it locally, set the environment explicitly, because the script's fallback path detection does not work when it is sourced. Use a build root outside this repo:

```bash
export CI_USE_ENV=1 CI_PROJECT_ROOT="$PWD" CI_BUILD_ROOT=/path/to/build-root
source ci/micropython.sh
cd "$CI_BUILD_ROOT"
ci_prepare_all
ci_cmake_configure pico_w_inky   # or pico2_w_inky
ci_cmake_build pico_w_inky
```

The `.uf2` files are copied to the current directory. `boards/*/version.py` is generated by the build and gitignored.

## Testing

CI only lints and builds. Behaviour changes have to be checked on a real board, so say so when a change has not been tested on hardware.

## Working with the board

Use `mpremote` over USB. `mpremote connect /dev/ttyACM0 run file.py` runs a file without installing it, and `mpremote connect /dev/ttyACM0 cp file.py :main.py` installs it. Copy the existing `main.py` first if it hasn't been saved.

The user's frame runs MicroPython 1.19.1 from February 2023, which is much older than this repo's `modules/inky_frame.py`. It has no `sleep_for`, `turn_off`, `woken_by_*`, `rtc` or colour constants in `inky_frame`, and `str.endswith()` rejects tuples. Code that uses these fails on the frame even though it passes lint.

On USB the board never powers off, so a button can't wake it. Anything meant to respond to buttons on USB has to poll them, and power-off and wake behaviour can only be tested on battery.
